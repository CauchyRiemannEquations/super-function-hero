# Tangent Parkour 리디자인 기록

이 문서는 기존 코드에서 확인한 기준선과 이번 리디자인의 구조적 의도를 기록한다. 구현·테스트 완료 보고서는 별도의 실제 검증 결과를 기준으로 한다. 아래의 검증 항목은 수행 계획이며 통과했다는 주장으로 읽어서는 안 된다.

## 분석 기준

- 저장소: `CauchyRiemannEquations/super-function-hero`
- 기존 기준 커밋: `6fde041c3f27a611887f464abf2c75f08417a200`
- 기존 패키지 버전: `0.2.0`
- 분석한 원본: `src/App.tsx`, 모든 `src/game/*`, `src/components/*`, `src/style.css`, `src/main.tsx`, `index.html`, `vite.config.ts`, `scripts/standalone.mjs`, `public/favicon.svg`, 기존 구현·검증 문서.
- 리팩터링과 병행한 분석은 `git show HEAD:<path>`로 원본을 읽었다. 다른 작업자가 수정한 파일을 기존 구현으로 오인하지 않기 위한 조치다.

### 확인되지 않은 기능을 기존 기능처럼 다루지 않기

기준선에는 PWA manifest, service worker 등록, 오프라인 설치 흐름, BGM 트랙·재생기, 별도 스플래시 모듈, 스테이지 선택, 체크포인트, 코인, 스테이지별 Best Time 저장이 없었다. 따라서 이 기능의 부재는 삭제로 인한 회귀가 아니다. 기존 standalone HTML은 파일로 직접 열 수 있는 배포 형태이며 PWA와는 구분한다. 기존 CSS는 Google Fonts를 불러왔으므로 완전한 오프라인에서도 같은 글꼴이 제공된다고 보장하지 않는다.

## 유지할 비주얼과 감각

원본 `drawPlayer()`의 달리기는 `sin(tick × 17) × 12`로 팔다리를 과장하여 흔든다. 6px 잉크 관절선, 13px 반지름 흰 헬멧, 짧은 검은 바이저, 뒤로 휘날리는 Bézier 스카프는 이미지 파일 없이 그려지므로 경사 회전과 발사 squash/stretch에 바로 적용할 수 있다. 원본 기술별 고정 기울기를 지형 접선과 비행 방향에 따른 몸 회전으로 바꾼다. 그림의 발 위치와 충돌 기준점은 명시적으로 맞춰야 한다.

배경의 태양·구름·건물은 각각 약 `0.015`, `0.06`, `0.12 / 0.27`의 시차를 사용했다. 이 다층 구조는 속도감을 만드는 데 재사용할 수 있다. 다만 화면 전체의 교재형 격자와 직선 옥상 바닥을 새 그래프 길보다 강하게 그리면 접선 지형의 의미가 흐려지므로 시각적 우선순위를 변경한다.

자취의 밝은 중심과 넓은 희미한 외곽, 발사 파티클, 짧게 커지는 라벨, 선택적 흔들림은 기존 표현 문법을 이어간다. `prefers-reduced-motion`에서 흔들림과 불필요한 이동 효과를 줄이는 기존 배려도 유지한다.

## 새 게임 루프와 책임 분리

1. 메인 화면에서 Play를 누르면 Stage Select로 이동한다.
2. 선택한 StageData를 초기화하여 자동 달리기를 시작한다.
3. 지면에 붙어 있을 때 현재 그래프의 높이·미분값으로 위치와 몸 각도를 갱신한다.
4. 탭 한 번이 현재 지점의 접선 방향 속도로 캐릭터를 발사한다. 공중에서는 중력으로 속도를 갱신한다.
5. 이동 구간을 검사하여 코인·장애물·착지·체크포인트·목표를 해결한다.
6. 실패는 짧은 MISS 연출 후 최근 체크포인트에서 재개한다. 목표 도달은 시뮬레이션을 멈추고 전체 자취를 보여준다.
7. 결과는 시간·코인·점프·Perfect 착지·콤보·Best Time을 표시한다. 다음 스테이지·재도전·선택 화면을 제공한다.

React는 메뉴·HUD·결과·설정 및 느린 상태 전달을 맡고 Canvas는 지형·캐릭터·자취·순간 효과를 맡는다. 계산·입력·저장·스테이지 데이터는 브라우저 그림 코드와 분리하여 테스트 가능한 경계를 둔다. 기존 엔진의 수명 관리와 화면 서비스는 그대로 활용하면서 전투 규칙을 새 시뮬레이션으로 교체하는 리팩터링이다.

### 함수와 좌표

함수는 지형별 데이터로 표현한다. 다항식 계수·원점·x/y 배율·유효 구간처럼 직렬화 가능한 필드가 적합하며, 함수 문자열을 `eval`하는 방식은 필요하지 않다. 동일한 평가기를 렌더링, 접선, 착지 판정, 결과 피드백에 사용하여 보이는 길과 실제 물리가 어긋나지 않게 한다.

수학 좌표의 y는 위쪽이 양수이고 Canvas y는 아래쪽이 양수다. 정규화된 접선은 수학 좌표에서 `(1, f'(x)) / sqrt(1 + f'(x)^2)`이며, 화면 속도로 옮길 때 y 부호를 반전한다. x/y 배율이 다르면 기울기도 `yScale / xScale`을 반영해야 한다. 양의 미분값이 화면 위쪽 발사로 보이는지 명시적으로 검사한다. `atan`만 계산하고 기울기의 부호나 좌표 변환을 혼합하면 핵심 학습 경험이 뒤집힌다.

점프의 초기 속도는 접선 방향이며 이후 중력을 받는다. 접선 위에 보이지 않는 추가 수직 도약을 붙이는 경우 접선 방향이 흐려지므로 감각 조정은 먼저 속도·중력·지형·목표 배치·착지 허용 범위에서 수행한다. 음의 기울기와 영에 가까운 기울기도 유효한 플레이 방향이어야 한다.

### StageData와 런타임 상태

StageData에는 id·이름·시작 지점·그래프/플랫폼·코인·hazards·checkpoints·goal·가이드 정책·Perfect 허용 구간·선택적 점프 제한 등 코스 정의를 둔다. 수집 여부, 활성 체크포인트, 현재 속도, 자취, 점수는 매 실행에서 만들어지는 별도 상태다. 재도전이 원본 데이터를 변형하지 않게 한다.

Stage 1–3은 지형을 보는 즉시 발사 방향을 이해할 수 있도록 접선 가이드를 제공한다. Stage 4–5는 짧거나 선택적인 가이드로 줄일 수 있다. 초반 직선·완만한 포물선에서 수평·급상승·음의 기울기로 진행한 뒤 Stage 5의 삼차 곡선과 선택적 수집 루트를 제공한다. 목표는 함수 이름 고르기가 아니라 점프 시점 고르기다.

착지는 하강 중 이동 구간과 실제 지형을 비교한다. 작은 위치 오차는 지형에 붙여 주되, 밑에서 올라가는 캐릭터가 플랫폼에 잘못 붙거나, 큰 점프가 얇은 플랫폼을 통과하거나, 같은 지형에 즉시 재착지하여 발사가 취소되지 않도록 한다. 그래프를 따라 달리는 속도는 수평 속도 고정과 접선 길이 고정 중 선택 기준을 분명히 해야 가파른 구간이 무조건 빨라지는 우연을 피한다.

체크포인트 재개는 어떤 수집·점프·콤보 상태를 복구할지 정해야 한다. 재개 전에 UI 입력 버퍼와 순간 효과를 지우고, 지속 시간은 결과 시간에 포함하여 실패를 반복해도 Best Time이 유리해지지 않도록 한다. 저장 실패·잘못된 JSON·이전 버전 데이터는 플레이를 막지 않아야 한다.

전체 자취는 원본의 짧은 잔상과 별도의 데이터다. 결과 카메라는 유효 경로의 bounds를 이용해 x/y에 같은 배율을 적용한다. 필요한 샘플 간격과 개수 제한을 두어 다섯 스테이지 반복 플레이에서도 배열이나 효과가 무한히 늘지 않게 한다.

## 확장 경로

이번 vertical slice의 필수 범위는 Stage 1–5다. 아래 내용은 이후 확장을 위한 설계 방향이며 보스·새 아이템이 이번 버전에 구현되었다는 뜻은 아니다.

- **새 함수:** 데이터 정의와 순수 높이/미분 평가기에 타입 하나를 추가하고, 같은 평가기를 렌더·점프·착지에서 호출한다. 엔진 내부에 스테이지별 분기문을 추가하지 않는다.
- **움직이는 플랫폼/목표:** 기준 위치와 주기·진폭·위상 또는 웨이포인트를 데이터로 정의한다. 런타임 시뮬레이션 시간으로 현재/이전 위치를 계산하고 상대 이동 구간으로 접촉을 판정한다. 화면 프레임 시간에 의존하지 않아 재현성을 유지한다.
- **아이템:** 코인·링·보석은 수집 동작과 표시 타입을 분리한다. 수집 경로는 선택적이어야 하며 클리어 조건에 불필요한 정답 검사를 넣지 않는다.
- **보스:** BossData가 phase 목록을 소유하고, 각 phase가 사용하는 지형 세트·약점 크기/위치/이동·가이드 정책·장애물·점프 제한을 정의한다. 공중 접촉/접근 각도 이벤트가 약점에 데미지를 전달한다. 1페이즈 큰 고정 약점과 가이드 → 2페이즈 작은 움직이는 약점과 삼차 지형 → 3페이즈 무가이드·장애물·점프 제한을 데이터로 조합할 수 있다.
- **여러 루트:** 플랫폼·코인 배치를 선택적 경로로 정의한다. 목표 도달만 필수이고 수집·Perfect·시간은 독립 기록으로 평가하여 빠른 경로와 수집 경로의 선택을 유지한다.

## 검증 범위와 제한

원본에는 Node test runner/tsx 단위 테스트 14개와 과거 브라우저 검증 JSON·PNG가 있었다. 원본 테스트는 기술 궤적·스킬 입력·CORE/Gate 전투·하층 급강하를 검증하므로 개편 후 그대로 통과시키는 것은 새 게임의 정확성 증거가 아니다. 과거 캡처와 통과 숫자는 이 버전의 검증 결과에 재사용하지 않는다.

필요한 자동 검증은 새 물리의 위험한 경계를 중심으로 구성한다.

- 다항식 높이·미분과 x/y 배율, 양/음/영 기울기에서 발사 속도 방향.
- 120Hz 스텝의 중력, 그래프 따라 달리기, 플랫폼·그래프 하강 착지, 위에서/밑에서의 접촉, 고속 이동 구간 충돌.
- 체크포인트 복구, 입력 한 번에 점프 한 번, 만료·일시정지·재시작 후 남은 입력 제거.
- 코인 중복 수집 방지, Perfect/콤보 허용 범위, 목표·결과 진입 한 번, StageData 초기화 독립성.
- 모든 다섯 코스에 실제 접선 점프로 도달 가능한 클리어 경로와 선택적 수집 경로가 존재하는지 고정 입력 시뮬레이션으로 검사.
- Best Time은 완주 시에만 갱신되고 느린 기록이 빠른 기록을 덮지 않으며 잘못된 저장 데이터에서도 시작 가능함.
- 뷰포트 균일 배율과 최소 가로 화면의 플레이 면적.

실제 브라우저에서는 메인 → Play → Stage Select → Stage 1–5 → Result의 전체 경로, 화면 탭과 키 입력, 결과 기록의 새로고침 후 유지, pause/visibility, 음소거, 재시작, standalone HTML을 확인한다. 모바일 가로 최소 `844×390`·`740×360`, 세로 `390×844`, 안전 영역·리사이즈·회전 안내를 확인한다. Fullscreen 또는 방향 잠금이 거절되어도 게임을 사용할 수 있어야 한다.

직접 플레이 검토는 발사 방향을 눈으로 이해할 수 있는지, 어디서 탭할지 고민하게 되는지, MISS 후 재시도가 빠른지, 자취가 독립된 그림처럼 남는지에 초점을 둔다. 몇 번의 플레이나 자동 통과는 재미·교육 효과를 입증하지 않는다. 브라우저 에뮬레이션은 실제 iOS/Android 손가락 가림·주소창·노치·오디오 정책·성능·방향 잠금을 보장하지 않으므로 기기 검증 여부를 결과 보고서에 분리해 적는다.
