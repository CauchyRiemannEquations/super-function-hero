# Super Function Hero — 원래 MVP 기획

이 문서는 사용자가 요청한 첫 MVP의 요구사항을 정리한 것입니다. 현재 구현 상태는 README와 IMPLEMENTATION.md, 최신 제안은 NEXT_STEPS.md를 함께 확인하세요.

## 목표와 핵심 콘셉트

**“수학 함수 그래프가 곧 캐릭터의 액션 기술이 되는 횡스크롤 액션게임.”**

교육용 수학 퀴즈처럼 문제를 읽고 답을 고르는 게임이 아닙니다. 플레이어가 함수를 선택하면 캐릭터가 실제로 그 함수의 형태를 따라 움직이고, 그 움직임으로 적을 공격하거나 장애물을 피합니다.

옛날 슈퍼액션히어로의 **단순한 입력 + 즉각적인 액션 + 콤보 + 짧은 미션**의 손맛을 참고하되, 디자인이나 캐릭터를 복제하지 않습니다.

완성형 게임이 아닌 **이 아이디어가 실제로 재미있는지 검증할 수 있는 고품질 MVP**가 목표입니다.

## 1. 핵심 게임 루프

화면은 2D 횡스크롤입니다. 캐릭터는 화면 왼쪽에 위치하고 기본적으로 오른쪽으로 자동 이동합니다. 적이나 장애물이 다가오면 화면 아래 함수 버튼으로 기술을 사용합니다.

함수 선택은 단순한 점프 애니메이션이 아닌 실제 함수 형태를 기반으로 한 궤적 이동이어야 합니다. 초기 기술은 다음 네 가지로 제한합니다.

| 함수 | 역할 | 의도 |
|---|---|---|
| `y = x` | 직선 대시 | 앞쪽 적을 빠르게 관통하거나 가까운 거리를 이동 |
| `y = x²` | 위로 치솟는 포물선 어퍼컷 | 공중 적 또는 높은 아이템 공격 |
| `y = -x²` | 공중에서 아래로 내려찍기 | 아래쪽 적 또는 착지 공격 |
| `y = sin x` | 물결 이동 | 높낮이가 다른 여러 적을 연속 공격하거나 장애물 회피 |

현재 위치를 기준으로 함수 형태를 정규화합니다. 수학식을 그대로 픽셀 좌표에 대입하지 않습니다. 엄밀한 실제 좌표값보다 학생이 함수의 개형을 명확하게 느끼는 것이 중요합니다.

## 2. 가장 중요한 디자인 원칙

**“문제 표시 → 정답 함수 선택 → 맞았습니다” 형태는 금지합니다.**

함수 선택 자체가 공격·회피·이동입니다. **수학을 풀고 나서 게임을 하는 것이 아니라, 수학이 곧 조작법이어야 합니다.**

처음에는 함수 이름을 몰라도 움직임을 보고 플레이할 수 있어야 합니다. 반복 플레이하면서 포물선, 위로 열린/아래로 열린 포물선, 사인 곡선의 주기적 움직임, 직선적 변화를 자연스럽게 체감합니다.

## 3. 조작

PC와 모바일을 모두 지원합니다.

- 키보드 1 → `y=x`
- 키보드 2 → `y=x²`
- 키보드 3 → `y=-x²`
- 키보드 4 → `y=sin x`
- 모바일 → 화면 아래 네 개의 큰 터치 버튼

버튼은 계산기나 문제집처럼 보이면 안 됩니다. 각 함수에 작은 그래프 아이콘을 함께 표시하고 게임의 스킬 버튼처럼 디자인합니다. 예: `/ x`, `∪ x²`, `∩ -x²`, `∿ sin x`.

최신 피드백에서는 모바일 가로 화면과 인게임 버튼 배치를 제안했습니다. 이는 원래 구현과 구분되는 다음 UX 실험입니다.

## 4. 즉각적인 타격감

함수를 누른 순간 반응하고 입력 지연이 느껴지지 않아야 합니다.

- 짧은 화면 흔들림과 타격 순간 hit stop.
- 적 피격 시 작은 knockback.
- 그래프 궤적 잔상과 파티클.
- 짧은 효과음.
- 콤보 숫자 확대, PERFECT 표시.
- 다중 적 공격의 연속 타격 피드백.

과도하게 정신없는 화면은 피합니다. 기술 궤적은 약 0.5–1초 남았다가 자연스럽게 사라집니다. 플레이어가 “내가 지금 포물선을 탔구나”라고 즉시 알아볼 수 있어야 합니다.

## 5. 콤보와 점수

연속 타격은 `COMBO ×2`, `×3`, `×4`처럼 표시합니다. 정확한 타격에는 PERFECT. 웨이브 다중 타격에는 `WAVE HIT ×3`, `x² → -x²` 연속 성공에는 `PARABOLA COMBO` 같은 특별 연출을 사용할 수 있습니다.

점수는 단순하게 유지합니다. 예: 처치 +100, PERFECT +50, 콤보 배수 적용.

## 6. 짧은 스테이지 하나

30–45초의 미션 하나를 만듭니다. 예시 흐름:

1. 게임 시작.
2. 지상 적 → 직선 돌진.
3. 공중 적 → 어퍼컷.
4. 아래쪽 적 → 내려찍기.
5. 높이가 다른 적 3마리 → 웨이브.
6. 어퍼컷 → 내려찍기 콤보 구간.
7. 마지막 적 무리.
8. CLEAR.

처음 플레이해도 적 배치와 그래프 모양으로 알맞은 움직임을 추측할 수 있어야 합니다. 다른 함수를 사용했다고 즉시 실패하지 않습니다. 적을 놓치거나, 장애물에 닿거나, 콤보가 끊기거나, HP가 감소하는 정도로 처리합니다.

## 7. HP와 실패

HP는 약 3칸. 적 또는 장애물과 충돌하면 HP 1 감소, HP 0이면 실패합니다. 실패 후 Restart를 누르면 로딩 없이 즉시 재도전할 수 있어야 합니다.

## 8. 캐릭터와 비주얼

복잡한 일러스트보다 스틱맨 또는 매우 단순한 캐릭터를 사용합니다. 디자인보다 움직임이 중요합니다.

- 밝고 경쾌한 모바일 캐주얼 분위기.
- 수학 교재 느낌 금지.
- 단순한 도시/공간/사이버 러닝 배경.
- 명확한 그래프 궤적.
- 어퍼컷은 실제로 강하게 치솟고, 내려찍기는 확실히 아래로 꽂히며, 웨이브는 물결 이동이 눈에 보여야 함.

## 9. 카메라와 예고

플레이어를 화면 정중앙에 고정하지 않습니다. 약간 왼쪽에 두어 앞쪽 상황을 더 많이 보이게 합니다. 적 등장 전에 시각적 예고를 두고, 함수 버튼을 고를 최소 반응 시간을 제공합니다.

초기 속도는 빠르지 않게 설정합니다. MVP에서는 점진적 속도 상승보다 조작감 검증을 우선합니다.

## 10. 기술 구현

웹 기반. 권장 스택은 React, TypeScript, Vite, HTML Canvas 또는 Phaser입니다. 현재 프로젝트에 더 적합한 기술이 있다면 판단해서 사용할 수 있습니다.

`requestAnimationFrame` 또는 엔진 update loop를 사용합니다. CSS transition만으로 캐릭터 이동을 구현하지 않습니다. 게임 좌표와 시간으로 위치를 계산하고, 함수 이동 중 충돌 판정이 안정적으로 동작하며, 모바일 브라우저에서도 부드럽게 실행되어야 합니다.

## 11. 궤적 정규화

기술 입력 당시 현재 위치를 시작점으로 잡습니다. 진행도 `t ∈ [0,1]`에 따른 normalized trajectory를 사용할 수 있습니다.

- 직선: 직선 형태.
- `x²`: 아래에서 위로 강하게 상승하는 포물선.
- `-x²`: 위에서 아래로 내려찍는 포물선.
- 사인: 최소 1–1.5주기의 명확한 파동.

화면의 y축 방향은 수학 좌표와 반대임을 고려합니다. trail도 캐릭터가 실제로 이동한 좌표로 그립니다.

## 12. 개발 모드 디버그

개발 중에만 다음을 제공하고 프로덕션에서는 숨깁니다.

- FPS, 캐릭터 x/y, 현재 함수.
- hitbox 표시 on/off.
- 이동 속도 조절.
- 적 spawn 테스트.
- 무적 모드.
- 각 함수 즉시 테스트.

## 13. 범위 제한과 우선순위

처음부터 만들지 않을 기능: 로그인, 서버, 랭킹, 계정, 스킨 상점, 수십 개의 함수, 30개 스테이지, 복잡한 스토리, 멀티플레이, 과도한 업그레이드.

목표는 **네 함수 기술을 눌렀을 때 게임으로서 손맛이 있는지**입니다.

우선순위:

1. 입력 반응성.
2. 캐릭터 움직임.
3. 궤적의 시각적 명확성.
4. 타격감.
5. 콤보의 재미.
6. 다시 해보고 싶은 느낌.

## 14. 작업 방식과 완료 조건

저장소를 먼저 분석하고 새 프로젝트라면 구조를 만듭니다. 구현 전에 게임 루프, 궤적, 캐릭터 상태, 적/충돌, 파일 구조를 간단히 설명합니다. 문서만으로 끝내지 않고 실제 플레이 가능한 상태까지 구현합니다.

직접 실행해서 시작, 키보드, 모바일 터치, 네 함수의 구분, 적 충돌, 콤보 증가, HP 감소, Game Over, Restart, CLEAR, 콘솔 오류, 모바일 버튼 잘림을 확인합니다. 가능하면 실제 화면을 캡처하고 어색한 움직임이나 UI를 한 차례 수정합니다.

최종 보고는 구현 내용, 실행 방법, 주요 파일, 지금 확인할 재미 요소, 다음 단계 후보를 간단히 정리합니다.
