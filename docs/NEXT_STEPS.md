# 다음 UX 실험: 모바일 가로 + 인게임 스킬 버튼

상태: **제안 / 논의 예정. 아직 구현하지 않음.**

사용자의 실제 플레이 피드백은 “재밌는데 모바일 가로 환경으로… 직선 무브 버튼을 인게임 내에 넣으면 좋을 듯”입니다. 이는 게임의 핵심 재미에 대한 긍정적 첫 반응이자, 터치 조작과 화면 배치를 다음으로 검증하고 싶다는 제안입니다.

## 원하는 변화

- 가로 방향 휴대폰에서 게임 화면이 중심이 되는 플레이 환경.
- 현재 페이지 아래의 직선 대시 버튼을 실제 플레이 화면 안에 배치.
- 네 함수 기술과 콤보·궤적의 읽기 쉬움을 유지.
- 게임을 시작한 뒤 페이지 스크롤 없이 조작할 수 있는지 확인.

## 아직 결정되지 않은 것

- 직선 대시만 옮길지, 네 스킬 모두 옮길지.
- 오른쪽 하단 2×2 배치, 한 줄 배치, 좌우 엄지 분산 배치 중 무엇이 좋은지.
- 세로 화면에서도 전체 플레이를 지원할지, 가로 화면을 부드럽게 권장할지.
- 인게임 버튼의 크기, 불투명도, 입력 영역과 화면 안전 여백.

## 논의 후보

| 안 | 예상 장점 | 확인할 점 |
|---|---|---|
| 오른쪽 하단 2×2, 네 기술 | 한쪽 엄지로 네 기술 접근 가능 | 오른쪽 앞의 적과 내려찍기 착지를 가릴 수 있음 |
| 좌우 2개씩 분산 | 두 엄지로 상승→하강 연결을 나눌 수 있음 | 양쪽 모두 게임 시야를 사용할 수 있음 |
| 직선 대시 크게 + 다른 기술 3개 | 사용자의 직선 버튼 아이디어를 가장 작게 시험 | 대시만 과도하게 쓰게 되는지 확인 |

위 장점은 설계 가설이며 실제 검증 결과가 아닙니다.

## 작은 검증 기준

1. 실제 휴대폰 가로 화면에서 네 기술 버튼이 화면 안에 보이고 눌리는가?
2. 버튼 때문에 적 등장, 플레이어, 중요한 궤적이 가려지는가?
3. 브라우저 주소창과 기기 안전 영역을 포함해도 터치 영역이 유지되는가?
4. 첫 플레이에서 각 기술의 움직임을 설명 없이 구분하는가?
5. 두 번째 플레이에서 웨이브 다중 타격과 상승→하강 콤보를 스스로 시도하는가?
6. 실패 후 재시작이 빠르고, 다시 하고 싶다는 반응이 나오는가?

먼저 버튼 배치 한 안만 선택해서 구현하고 비교합니다. 새로운 함수·서버·계정·업그레이드 시스템은 이 실험의 범위에 포함하지 않습니다.
